The gap

Your projects know how things work. Your agents can do the work.

Between the two, there is you, copying prompts.

Cerea takes you out of the middle.

The bridge

Know, reach, act.

Most assistants stop at knowing. Most agents start by knowing nothing. Cerea is built so the three are one conversation.

01

Know

Projects, knowledge bases and memory: the context that makes an answer yours and not the internet's.

02

Reach

Your services, remote or on your own computer, in one place — loaded when a task needs them.

03

Act

Coding agents on your machines, a browser that is really yours, code that can do what no tool can.

And the three share one set of credentials, held server-side. An agent on your laptop can use a connector that lives on your server, because Cerea makes the call — with your credentials, which never leave it.

The parts you don't have to assemble

Nine tools, one install.

Most self-hosted setups are nine installs and a weekend, with a knob for every one of them. Cerea ships the whole desk, with the defaults already chosen.

  • document reader
  • office suite
  • code sandbox
  • connector bridge
  • browser automation
  • coding agents
  • model gateway
  • single sign-on

Licence

Fully open. All of it.

Not open core, and not source-available. There is no paid edition holding back the parts that make it useful, and no feature that appears only once someone signs a contract.

  • One licence, the whole stackChat, knowledge, connectors, browser use, code, agents — Apache-2.0, in one repository.
  • No open coreWhat you can read is what actually runs.
  • No source-available tierNo “look but don't touch”, no field-of-use clause to read twice.
  • No telemetry, no phone homeNot even an opt-out switch — there is nothing to turn off.
  • Fork it, host it, build on itApache-2.0 permits all three. The NOTICE file keeps the attribution honest.

What it does

The ordinary things, done properly.

The whole desk: knowledge, files, documents, code, a browser, agents.

01

Projects and knowledge

Instructions, documents and memory every new chat starts from — searched with RAG, shareable with people or groups.

02

Files read on arrival

PDFs, Office documents, scans, images and recordings: understood once, available everywhere in the conversation.

03

Office files, made and edited

Word, Excel, PowerPoint and PDF — created, revised, and forms filled in, scanned ones included. Each edit a new version.

04

Code when you need it

A sandbox with the data and office stack, for the work a form cannot do — opening a large export and answering from it.

05

Connectors

Your services, remote or on your own laptop, brought in only when a task needs them — no context bloated with tools it will not use.

06

Browser use

A real browser on your machine, signed in as you: it searches, fills, pages through and downloads — and asks before anything commits.

07

Image generationWith Pystino

A picture from a sentence, in the conversation where you asked for it.

08

TranscriptionWith Pystino

Drop a recording in the chat and the transcript is there, ready to search or quote.

09

Web searchWith Pystino

Run by your deployment's own backends, not rented from someone else's index.

Agents

Your machines, your rules.

opencode, goose, or Claude Code — driven from the chat, running where the code already is.

Run them anywhere

On your computer, in a container, in a workspace you choose. Install once; the pairing survives restarts.

Decide what they may do

Ask, Auto or Allow, per session. On Auto a reviewer reads the risky ones, and every action is on the record.

Put more than one to work

Helpers delegate to other sessions, on other models. A session can fork from any answer and keep going.

Connectors relayedThe tools you switched on for a session, across machines — with credentials that stay on the server.
Changes and filesThe diff before you accept it, files to open and edit, a terminal when you want one.
Schedules and your inboxA prompt on a timetable; anything that needs you waits in one inbox, on any device.
Billing that follows the personEvery engine that goes through the gateway is metered to the person; Claude Code on your own subscription bypasses it.
The computer sets its own limits. Cerea cannot loosen them over the link.
Your credentials stay on the server. They never reach the machine.
Every device is paired by you, and can be revoked by you.
Nothing here asks you to trust a prompt.

Privacy and control With Pystino

Enforced at the gateway, not in a prompt.

  • Per-person accounts and quotas — spend follows the person, not the card on file.
  • Model access by group, decided in the console and enforced on every call.
  • Redaction of what should not leave the building, before it reaches a model.
  • One console for who may use what, and what it cost.

“A chat that reaches your files and your machines is only worth having if someone can say who it acted for, and what it cost.”

Cerea and Pystino

Two halves, each useful alone.

Each solves a different problem and each runs on its own. Together they are the intended setup.

This repository

Cerea

Serves the people using models.

  • The chat, its knowledge, its artifacts and its files
  • Connectors, browser use and code
  • galopin, pairing coding agents on a person's own machine

The gateway

Serves the organisation paying for them.

  • An OpenAI-compatible gateway with per-user and per-group accounting
  • Quotas, redaction, model access, an admin console
  • Web search, document reading, images, transcription — metered

Cerea alone runs against any OpenAI-compatible endpoint with one shared key. Pystino alone serves any OpenAI or Anthropic client. Together, the chat calls Pystino's /v1 with each person's own sign-in token — so spend, quotas and model access follow the person.

Quick start

One compose file, three shapes.

The deploy kit is a single compose.yaml, a documented .env.example and a ./configure script.

The default: everything, together

The chat, Pystino and its console, a bundled identity provider, a TLS proxy and the add-ons — one stack to stand up.

  • ✓Per-person spend, quotas and model access through the gateway
  • ✓Web search and document reading that stay inside your deployment
  • ✓Images, transcription and metered coding agents

Chat only, against a central Pystino

./configure --preset satellite — your chat joins a gateway someone else operates, and gets the metered features.

  • ✓Your users, your sign-in, your knowledge bases
  • ✓Billing and quotas handled centrally
  • –You do not run the console or the identity provider yourself

Chat only, any endpoint

./configure --preset generic — no Pystino at all: one endpoint, one shared key.

  • ✓Chat, knowledge, artifacts, Office files, code, browser use, agents
  • –No per-person accounting, quotas or gateway models
  • ✓PDFs and images go to an OCR endpoint you name

What each shape gives and lacks is set out in the deployment guide.

terminal 
# fetch only the kit
curl -fsSL https://raw.githubusercontent.com/paoloviviani/Cerea/stable/kit/get-kit.sh | sh
cd cerea/kit
./configure
docker compose up -d
kit/ Chat-only installs: --preset satellite or --preset generic Agents and the browser need one more switch; the deployment guide lists them.
